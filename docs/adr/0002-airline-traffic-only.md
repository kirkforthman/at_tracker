# 0002 — Store airline traffic only

Date: 2026-10-23 · Status: accepted

## Context
OpenSky `/states/all` returns every aircraft in the bounding box (private, business, military,
airline). It has no server-side filter by operator; the `icao24` parameter needs an explicit list of
airframes. The project only needs airline traffic, and there is no reason to keep data about private
or military flights.

## Decision
Filter each response **in memory** before anything is written (DB, logs, caches, fixtures). Keep a
state vector only if:
1. the callsign is airline-shaped (`^[A-Z]{3}\d[0-9A-Z]{0,4}$`),
2. its 3-letter prefix is on the allowlist (`ingest/at_ingest/data/airlines.csv`), and
3. its icao24 is outside blocked ranges (US military `AE0000–AFFFFF`).

An allowlist, not a denylist, because military transports (`RCH`) and business-jet charters (`EJA`,
`LXJ`) also use 3-letter prefixes. Dropped traffic leaves only counts (`received`, `kept`) and
per-prefix counts of airline-shaped callsigns that were off the allowlist, used to maintain it.

## Consequences
- An airline missing from the allowlist is invisible until added; reviewed from the unmatched counts.
- First live measurement (P0, 2026-10-23 17:21 UTC, CONUS): 8,732 received, 3,487 kept (40%).
- Committed test fixtures for aircraft-level data (OpenSky, adsbdb) are **synthetic**, generated by
  `ingest/tests/fixtures/generate_synthetic.py` and labelled `_synthetic`. Real responses are kept
  only in the gitignored `ingest/recordings/`, still filtered. This keeps recorded OpenSky data out of
  a public repository.
